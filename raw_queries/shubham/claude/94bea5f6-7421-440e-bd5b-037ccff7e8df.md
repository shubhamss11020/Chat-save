## Claude (2026-09-15T10:52:04.647Z)

Here's how to restore a Postgres dump on your local setup (Windows):

## 1. Check what kind of dump file you have
- **Plain SQL** (`.sql`) — human-readable text, starts with `--` comments / `CREATE TABLE` statements.
- **Custom/compressed format** (`.dump`, `.backup`, or no extension) — binary, made with `pg_dump -Fc`.

If unsure, open the first few lines: `PGDMP` at the top = custom format binary.

## 2. Make sure PostgreSQL client tools are on PATH
Check with:
```powershell
psql --version
pg_restore --version
```
If not found, add PostgreSQL's `bin` folder (e.g. `C:\Program Files\PostgreSQL\16\bin`) to your PATH.

## 3. Create an empty target database
```powershell
psql -U postgres -c "CREATE DATABASE mydb;"
```
(Replace `mydb` and `postgres` user as needed — it'll prompt for the password.)

## 4a. If it's a plain `.sql` file
```powershell
psql -U postgres -d mydb -f "C:\path\to\dumpfile.sql"
```

## 4b. If it's a custom-format `.dump`/`.backup`
```powershell
pg_restore -U postgres -d mydb "C:\path\to\dumpfile.dump"
```
Add `-v` for verbose output, and `--no-owner --no-privileges` if the original roles don't exist on your machine and you want to avoid ownership errors.

## 5. Verify
```powershell
psql -U postgres -d mydb -c "\dt"
```
This lists the tables to confirm the restore worked.
