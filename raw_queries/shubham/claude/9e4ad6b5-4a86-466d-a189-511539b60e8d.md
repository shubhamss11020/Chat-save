## Part 1: Setup

### 1. Connect an MCP server
Codex shares one config between the CLI, the IDE extension and the desktop app: `~/.codex/config.toml`. On Windows that is `C:\Users\shubh\.codex\config.toml`.

**Option A: UI.** Go to Settings → MCP servers → Add server. Choose STDIO (a local command) or Streamable HTTP (a URL).

**Option B: CLI.**
```powershell
codex mcp add my-server -- npx -y @some/mcp-server
codex mcp list
```

**Option C: edit the config directly.**
```toml
[mcp_servers.my-local]
command = "node"
args = ["C:/path/to/server.js"]
env = { API_KEY = "xxx" }

[mcp_servers.my-remote]
url = "https://example.com/mcp"
bearer_token_env_var = "MY_TOKEN"
```
For OAuth servers, run `codex mcp login my-remote`.

**Verify:** restart the app, then ask "list the tools you have from my-server" and call one tool.

### 2. Add custom skills
Codex skills use the same format as Claude skills: a folder containing a `SKILL.md` file with `name` and `description` frontmatter.
- Global: `~/.codex/skills/<skill-name>/SKILL.md`
- Project: `<repo>/.agents/skills/<skill-name>/SKILL.md`

You can reuse your Claude skills by copying the folders over.

**Verify:** type `/skills` or `$skill-name` in the composer, and check that it also triggers implicitly from a prompt that matches the description.

### 3. Add a project
- Open Codex desktop and choose Add project / Open folder. Point it at `C:\Users\shubh\OneDrive\Desktop\POC`.
- Create `AGENTS.md` in the repo root. It works like CLAUDE.md and holds build and test commands and conventions.
- Mark the folder as trusted so project-level `.codex/config.toml` is loaded.
