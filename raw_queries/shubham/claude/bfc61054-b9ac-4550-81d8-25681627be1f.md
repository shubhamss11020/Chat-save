## Claude (2026-10-12 09:36:15 EDT)

Chat-Save is a system that captures AI assistant transcripts (Claude, ChatGPT, Claude Code) and archives them as Markdown files in a GitHub repository. It separates ingestion from git writes, so a slow or unavailable GitHub doesn’t block capture.

Deployment roles

Hosted MCP server (e.g. on Render): Claude calls the save_chat_transcript tool, or posts to HTTP endpoints, and the server commits the transcript to GitHub.
Local desktop capture agent (PC/Mac): Watches local Claude Code transcript directories (~/.claude/projects), hashes content, queues changes in a local SQLite outbox, and delivers them to the hosted server or a local git repo.

Core principles

Transactional outbox: Snapshots and their delivery status are written to a local SQLite table (capture.db). If GitHub is down, items stay queued and are retried on later reconcile cycles.
Hash-based deduplication: Each conversation gets a SHA-256 digest over its platform, ID, title, and messages. Unchanged conversations are dropped before any disk write or commit.
Stateless FastMCP server: It runs with stateless_http=True, so each request is self-contained and survives container restarts, without long-lived SSE streams.
Identity resolved before tool execution: The user is determined from a ?user= query parameter, a per-user token map, or a Bearer token, and stored in context variables. The LLM never supplies its own username, so transcripts land in the correct user directory.

Components

auth.py: Token authentication and user binding.
mcp_server.py and main.py: The MCP tool and FastAPI REST endpoints (ingestion interfaces).
capture.py and outbox.py: Directory scanning, hashing, enqueueing, and draining the queue in batches of 25.
gitstore.py: Renders Markdown with frontmatter, takes a thread lock, commits, and does pull --rebase and push.
state.py: SQLite persistence for the outbox and scan signatures.
sources/: Platform adapters, starting with a Claude Code parser.

Data flows

Direct tool call (Claude Web/Desktop): Claude calls the MCP tool → auth binds the user → the MCP layer injects the user into the payload → gitstore takes a lock, writes raw_queries/<user>/claude/<id>.md, commits, rebases, and pushes → a success or failure result returns to Claude.
Background capture (desktop agent): On each reconcile interval, the agent checks file signatures for changes, parses changed transcripts, computes hashes, enqueues new snapshots as PENDING, and the outbox delivers them. Success marks an item DELIVERED. Failure increments the retry count and records the error.

Storage

capture.db has an outbox table (hash, JSON payload, status, retries, last error, timestamps) and a scan_state table (platform, thread ID, file signature, scan time).
The git archive is organized as raw_queries/<user>/<platform>/<conversation-id>.md. Each file has YAML frontmatter (conversation ID, platform, username, title, timestamps) followed by the messages.

Authentication options

Query parameter: /mcp?user=<name>&key=<token>, with MCP_AUTH_TOKEN set on the server.
Multi-user map: USER_TOKENS maps each token to a user.
Bearer header: Authorization: Bearer <token>.

Compared with the legacy “Threads OV” design

The legacy version was a single script of about 600 lines that ran synchronous git clone, rebase, and push on every request. It had high latency, lost data on crashes, produced frequent push conflicts, wrote duplicate files, and relied on hacked SSE paths. Chat-Save uses a layered module structure, a durable SQLite outbox, thread-serialized git writes with batched pushes, hash-based deduplication, and the standard FastMCP stateless protocol.
