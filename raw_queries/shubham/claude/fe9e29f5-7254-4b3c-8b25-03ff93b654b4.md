## Code changes needed

**1. `GET /mcp` returns the legacy SSE stream, not a Streamable HTTP response.** This is at [http_server.py:356-357](mcp_server/http_server.py#L356-L357).

- The branch is `elif scope["method"] == "GET": _handle_sse_raw`, and it fires for both `/mcp` and `/sse`.
- After `initialize`, a Streamable HTTP client does a `GET /mcp` to open its server-to-client stream. Under the spec it should get either a proper stream or `405`.
- What it gets is `event: endpoint`, which is the legacy protocol. Claude tolerates this. ChatGPT's client may treat it as a protocol error and abort discovery.
- **Fix:** only serve legacy SSE when `tail == "/sse"`. For `/mcp`, hand every method to `manager.handle_request`, which already returns a clean `405` for GET in stateless mode.

**2. The header-token auth can't be used from ChatGPT.** This applies to `hr`, `internal-team`, `intern` and `raj`. It's at [http_server.py:329-347](mcp_server/http_server.py#L329-L347).

- Today these identities return a `401` with no `WWW-Authenticate` header and no OAuth discovery endpoints. ChatGPT can't connect to them at all.
- **Fix options:**
  - Quick: use the path-secret identities (`ayan` and `staging_qa`), as the local test does.
  - Proper: add per-person secret URLs backed by `mcp_tokens`, or real OAuth with `/.well-known/oauth-protected-resource`.

**3. Tool errors are reported as success.** A failed DB call comes back with `isError: false` and the error text inside the JSON. The model sees a "successful" error, so a failed call reads as an empty result. Setting `isError: true` in `call_tool()` fixes that.
